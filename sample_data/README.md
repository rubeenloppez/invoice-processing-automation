# Synthetic demo data

`demo_input/` contains a fixed-seed portfolio batch generated by `python scripts/generate_sample_data.py`. All supplier names, invoice numbers, and amounts are fictional. There are no real people, addresses, tax identifiers, bank accounts, email addresses, or client documents.

The batch contains 40 constructible invoices: 22 in three CSV files, 15 in two XLSX files, and three in readable digital PDFs. It also contains one intentionally invalid CSV row, one corrupt PDF, and one unsupported TXT file. The CSV and XLSX files may contain multiple invoices; each PDF contains one. `expected_scenarios.yaml` identifies 19 known scenarios by stable source path and row number, with the expected issue or file status.

Run from the project root:

```text
python scripts/generate_sample_data.py
python scripts/run_demo.py
```

The generator uses seed `20260928` and refuses to ignore unexpected files in `demo_input/`. The verifier reads `demo_input/` directly and writes the official reports to `demo_output/`. Neither script uses the normal `input/` or `output/` directories. Re-generation is logically deterministic; XLSX/PDF metadata need not be byte-identical.
